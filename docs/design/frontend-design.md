# 锡院助手 · Windows 前端设计文档

> 版本 v1.0 · 2026-09-17 · 基于对官方融合门户（my.cwxu.edu.cn）与慧新E校（10.3.100.110）的实机走查
> 走查环境：真实账号登录门户全部页面 + SSO 桥进慧新E校（截图与 DOM 快照取证）

## 一、设计定位

**一句话**：把「信息墙式的政务门户」重做成「以今天为中心的个人校园工作台」。

- **单页面职责**：打开应用 3 秒内看到「现在最该知道的事」——今天有什么课、临近什么会、一卡通还剩多少钱、有没有新待办/公告。
- **桌面优先**：这是常驻 Windows 的客户端（托盘 + 系统通知），不是网页复刻；用原生感交互（命令面板、全局快捷键、深浅主题跟随系统）建立与网页版的体验差。
- **不做官方站内的深度流程**（选课、报销等仍在官方系统完成，客户端只做「看 + 提醒 + 直达」）。

## 三、功能重设计映射（官方功能 → 锡院助手）

原则：**官方有的做减法或直达，官方缺的做加法**；凡属「看一眼」的信息进卡片流，凡属「办一件事」的流程一律外链官方系统。

### 3.1 头像上传（用户点名案例，P0）

官方：裸文件框 + 三行红字要求。锡院助手：**上传即服务的三步弹层**。

1. 选图（或拖拽到弹层）→ 2. **1:1 裁切器**（圆形/方形预览，滚轮缩放拖动取景，默认方形框锁定 1:1）→ 3. **压缩导出**：Canvas 重采样至 ≤512×512，JPEG 质量 0.85 起步自动降质二分逼近 ≤200KB（默认 jpg；源图为 png 且 ≤200KB 时保留 png 选项），实时显示「原 2.4MB → 183KB」→ 上传。
- 实现选型见 §7（react-easy-crop + Canvas API，零新依赖负担）。
- 顺带解决：裁切结果同时用于客户端本地头像展示（不再依赖官方服务端清晰度）。

```
├──────────────────────────────────────────────────────────────┤

│              ╭──────────────────────────────────╮            │
```

### Dock 规格复刻（对齐 CampusLogin `DockNav.tsx`）

- **容器**：`fixed bottom-5 z-30` 水平居中；玻璃质感（半透明底 0.82/0.85、1px 亮边框、圆角 18px、双层阴影、两个伪元素做高光，不用 backdrop-filter 以保性能）；内容区 `pb-28` 预留不遮挡。
- **标签项**：纯图标（lucide 18px）无文字，文字走 hover 上浮 tooltip（250ms 延迟）+ `aria-label`；8 项：今日/资讯/待办/日程/应用/钱包/电费/设置。
- **激活态**：framer-motion 弹入的圆角胶囊 + 底部 3px 圆点指示条（spring stiffness 500 / damping 34 随激活项滑动）——**颜色用该项域色而非统一色**（今日=锡院紫、资讯=域紫、待办=琥珀、日程=湖蓝、钱包/电费=域绿、设置=中性灰），把「看颜色知道是哪类事」延伸到导航上。
- **磁吸放大**：鼠标 80px 范围内图标 scale 1→1.35、上浮 -14px（gsap quickTo expo.out 0.35s，RAF 节流；动画降级档位禁用磁吸，`prefers-reduced-motion` 下关闭）。
- **切换实现**：zustand `activePanel`（非路由）+ 持久化上次页面；`AnimatePresence mode="wait"` 弹簧过渡（进 y:8→0，退 0.04s 快出）+ `useDeferredValue` 快速连切只渲染最终面板。
- 依赖增量：**framer-motion**（指示条/过渡）、**gsap**（磁吸，可裁剪）；lucide-react 已在选型内。

### 首页「今日」线框（v2 定稿 · 用户拍板精简版）

> **用户决策（2026-09-17）**：首页去掉资讯中心、快捷应用、待办中心、会议、信息服务、课表卡片六个模块——首页只做「当下最重要的三件事」。资讯/待办/会议/应用均为独立页面（导航不变），靠 M5 系统通知推送到人，不靠首页堆叠。

- 被移除模块的去向：资讯→「资讯」页+M5 通知；待办→「待办」页+M5 通知；会议→「日程」页+M5 通知；信息服务→「应用」页服务分组；课表→独立「课表」页（§5.1）；首页快捷入口→固定 4-6 个动作按钮（查电费/充值/报修/办事大厅/全部应用），不是官方那种可排序应用堆叠。

- 余额低于阈值时钱包卡自动转 `--alert` 色并触发系统通知（M5）。


功能规格（按用户需求逐条落实）：

1. **教务自动导入**：登录态复用 CAS 会话 → SSO 进正方教务 → `POST /jwglxt/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151`（`xnm=<学年>&xqm=<学期代码：3=第1学期/12=第2/16=暑期>`，2026-09-17 实测通过）→ 解析 `kbList`（课程名/教室/教学班/节次 jc/周次位掩码 oldzc/考核方式）与 `xsxx`（学年学期）。教师身份课表接口同源，导入时按账号角色自动选端点（学生 `xskbcx_cxXsKb` 已验证；教师端点 M2.5 侦察）。
2. **导入/手动源隔离**：每门课带 `source: 'import' | 'manual'` 标签（用户口中「用户不可见标签」= 界面上以【导】角标呈现来源、但不打扰视觉）；**一切自动更新/调课解析只作用于 `source='import'` 的课程**，手动添加的课程永不触碰。
3. **自动对比更新**：每次导入新快照后与本地 diff（匹配键 `课程名+教学班 jxb_id`）：周次掩码/教室/节次有变化 → 仅更新匹配的导入课程并生成变更日志（「信息安全 教室 D4-207 → D4-305」）；新出现课程自动加入（source=import），消失课程标记「已停开」。
4. **调课通知自动调整**（override 模型，shiguangschedule 没有的部分，自建）：
   - 数据源：M5 公告流命中关键词（调课/调休/停课/补课/考试安排）的教务处/学院通知。
   - 两级解析：**L1 规则层**（正则+词表提取：课程名、原周次/星期/节次、新日期/新节次/新教室、生效范围）；**L2 置信分级**——要素齐全且课程名精确匹配已导入课程 → 高置信，自动应用并标记 `override.source=notice:<id>`；缺要素或匹配多门 → 低置信，进「待确认」列表由用户一键采纳/忽略。
   - 应用语义：override 叠加于导入课程之上（原数据保留可回滚）；通知撤回/修订 → 按通知 id 撤销对应 override。
5. **算法与数据模型移植**（来自 shiguangschedule，Apache-2.0）：`weeks: number[]` 显式周次列表（取代单双周标志位）、开学日↔周次互算（支持自定义周起始日）、重叠课程分列算法、默认节次表常量。渲染用 React absolute 定位重写（其 Compose 渲染不可复用）。
6. 作息时间表支持自定义（本校节次时间内置默认，可编辑）；支持手动添加课程（颜色自选、周期可跨周）；ICS 导出沿用 shiguangschedule 的展开式 VEVENT 方案。

- 正文/UI：`"Segoe UI", "Microsoft YaHei UI", system-ui`（Windows 原生，零加载成本）。

### 布局与签名

- 4px 基线栅格；卡片圆角 10px、1px 边线 + 极浅投影（阴影不做层级语言，边线和域色做）。

- 命令面板（Ctrl+K）不因 Dock 修改而弱化：仍是键盘党到任何地方的一条路径。
- 动效仅三处：页面切换弹簧过渡（120ms 级）、数字变化滚动（300ms）、Dock 磁吸；尊重 `prefers-reduced-motion`。

### 自评（防模板化检查）

- 不属于 AI 默认三型（奶油+赤陶 / 纯黑+酸绿 / 报刊细线），品牌紫锚定学校 VI、域色系统来自内容语义而非装饰。

- 风险点：紫在深主题易闷——深主题 brand 提亮至 `#8B5CF6` 档并降低使用面积。

## 附录 D · 2026-09-18 第二轮：头像裁切器与上传回学校

**触发**：用户选定「裁切器 **与** 上传回学校都要」，并追加三条约束——① 200KB 限制下**尽可能保留高分辨率**；② 增加「只改本机不上传」的选项；③ 本机头像的体积上限可以放宽。

### D1 门户头像上传协议（实测，两次真机上传取证）

| 项 | 实测结论 |
|---|---|
| 端点 | `POST /api/authc/users/portraitChange`，body 为 JSON，图片以 data URL 形式放字段里 |
| 鉴权 | JWT 直接放 `Authorization`（**不带 `Bearer` 前缀**），值为 `tryLoginUserInfo.data.tokenId`；另需 `loginUserId` / `loginUserName` / `loginUserOrgId`（取自媒体资料接口） |
| 防伪 | `csrfTimestamp`（毫秒时间戳）+ `csrfToken = md5("timestamp=<毫秒>,key=<门户前端常量>")`（小写十六进制）；密钥常量取自门户前端 bundle，**只存于源码 `crates/campus-auth/src/cas.rs`，文档与 wiki 一律不写明文值** |
| 其它头 | `X-Requested-With: XMLHttpRequest` |
| 成功判据 | 响应 `meta.success`；失败时保留服务端 `meta.message` 原样回显（已单测） |
| 服务端行为 | **按上传内容原样存储**（不做二次压缩/重编码）→ 所以「200KB 内尽量高分辨率」确实有意义，压缩责任全在客户端 |
| 官方原图 | `getLoginInfo.data.headPortrait` 实测仅 123×123（=1:1 小图），即校方原图分辨率本身很低 |

**结论**：上传链路可在纯后端完成（一个命令 = 取资料 → 现算 csrf → 上传 → 回读校验），不需要在门户页面里做任何注入或脚本。

### D2 客户端体积与分辨率策略（对应用户三条约束）

**分辨率不被显示尺寸吃掉**：`react-easy-crop` 的 `croppedAreaPixels` 给的是**原图像素**坐标，1200×900 源图 zoom=1 时方形裁切上限就是 900×900，与裁切框在屏幕上的显示大小无关。

| 路径 | 输出 | 上限 | 说明 |
|---|---|---|---|
| 仅保存到本机 | 边长 `min(1024, 裁切边长)`（不放大）；有透明通道出 PNG，否则 JPEG q0.92；PNG 超 2MB 回退白底 JPEG | **2MB**（放宽，原 512KB） | 超限文案「本机头像过大（上限 2MB）」 |
| 保存并上传学校 | 尺寸阶梯 `[1024,896,768,640,512,448,384,320]` 外层 × 质量阶梯 `[0.95…0.6]` 内层，取第一个 ≤200KB 的组合；源分辨率不足的档位 clamp 不放大 | **200KB**（校方硬限） | 超限文案「学校头像上限 200KB，请调小尺寸或质量」；上传成功后同时写本机 |

- **本地/学校两条路径的预估数字来自同一个编码函数**，保存时重算，因此界面显示的体积与实际落盘一致（已实测核对）。
- 学校路径先铺白底再编码 JPEG（JPEG 无透明通道，防透明区发黑）。
- 未登录时「保存并上传学校」不可用；后端命令同样独立守卫（返回「请先登录」）。
- 日志只打码用户名，**绝不记录 data URL**（头像 base64 体积大且属账号资产）。

### D3 真机验证（2026-09-18，真实账号）

| 场景 | 证据 |
|---|---|
| 本机保存 | `profile.json.localBase64` = 141385 字节 PNG 900×900，界面预估「约 139 KB」与实际一致；右上角账号头像与首页问候区头像同步更新 |
| 上传学校 | `getLoginInfo.headPortrait` 由 PNG 123×123 / 28657 字节 → JPEG 123×123 / 4852 字节，`officialFetchedAt` 刷新；界面提示「已上传学校」后 1.2 秒自动关闭，头像显示为账号真实头像 |
| 单元测试 | `cargo test -p campus-auth` 26 passed / 3 ignored（含 csrf 金标向量、portrait 解析与失败回显）；前端 `tsc --noEmit` 干净、`vite build` 通过 |

**踩坑**：裁切回调 `useCallback` 原本写在 `if (!open) return null;` 之后 → `open` 变化时 Hook 数量变化，React 19 直接卸载根节点（打开弹窗即白屏）。**规则：任何 Hook 必须声明在提前 return 之前**。

### F3 官网鉴权页导致的两类栏目差异与降级设计

官网正文页 URL 有两种形态，**抓取能力不同**（2026-09-18 实机 curl 验证）：

| 栏目 | 正文 URL 形态 | 抓取能力 |
|---|---|---|
| 校园要闻 / 校园快讯 / 教务处 / 学工处 / 团委（5 栏） | `www|jwc|xgc|tw.cwxu.edu.cn/info/<栏目>/<id>.htm` | 可正常抓取（容器为博达标准 `vsb_content*` / `v_news_content`） |
| 通知公告（columnId 9）/ 规章制度（5d2c45d23866497cb2bfe93e9f136bb2）（2 栏） | `www|xgc.cwxu.edu.cn/content.jsp?...wbnewsid=<id>` | **被官网鉴权开门页拦截**：无论带不带 Cookie/UA/Referer 都停在 `/system/resource/code/auth/auth.htm`（标题「系统提示」），且无 `/info/` 替代形式（404） |

**降级设计**：后端 `is_auth_wall` 三依据判定（HTTP 非 2xx / 重定向最终 URL 命中 auth.htm / `<title>` 精确「系统提示」）命中时返回 `needsBrowser=true` **正常返回**——对用户表述为「正文需在浏览器中查看 · 该栏目正文由学校官网鉴权保护」，引导浏览器打开原文；**不进错误态**（这不是故障，是站点行为）。正文抓取用裸 HTTP client 不带门户鉴权头（JWT 只发门户同源，绝不随正文抓取发往其他域名）。

### F4 数据纪律

- 前端只吃后端清洗过的 HTML 片段（域名白名单 + 标签/属性白名单在 `campus-portal::article` 完成），不二次清洗；CSP `img-src` 放行 `https://*.cwxu.edu.cn http://*.cwxu.edu.cn` 供正文官网图片显示，域名仍限校园官网。
- 分页不信服务端 `total`/`pageCount`（实测 pageSize=1 时返回 0），一律满页判断，不伪造页码。
- 待办条目字段按多候选键宽松映射（账号无真实数据未校准），真机出现数据后需校准——见计划文档遗留项。
- 正文抓取与浏览器打开共用 `is_allowed_info_url` 白名单（计划红线 3），`open_url_in_browser` helper 批次 3 `open_app` 复用。

### G2 图标代拉方案与降级

官方应用图标是**门户同源的受保护资源**（`zuul/docrepo/download?attachmentId=<appIcon UUID>`），前端（WebView 域）直连会因跨站 Cookie 拿不到会话而得到裂图。因此改为**后端代拉**：

1. `query_app_catalog` 把分组与钉选中出现过的图标附件 id 去重，**带门户会话并发代拉**（`buffer_unordered(4)`，对内网网关友好）；
2. 字节按**魔数**判 MIME（不信任响应 Content-Type——文档库静态资源常给 `application/octet-stream`），base64 编码为 `data:<mime>;base64,…` 填进 `iconUrl`；
3. **降级链**：服务端确认非图片（如返回 HTML 错误页）→ 记为 `None` 并同样缓存，防每次刷新重试；传输类失败 → 不缓存、下次目录刷新自动重试；最终拿不到图标 → `iconUrl: null` + 前端占位图标。**图标失败永不阻塞目录返回**（单图标失败不影响其余图标与其余条目）。

### G3 两种 URL 校验的语义分工

本批引入第二个 URL 校验函数，两者**语义不同、不可互换**（单向单测钉死，防止日后误"统一"）：

| 校验 | 规则 | 适用场景 | 为什么 |
|---|---|---|---|
| `is_allowed_info_url`（**域名白名单**，批次 2） | 仅 `*.cwxu.edu.cn`（host 精确后缀匹配） | ① 后端要**抓取内容**的 URL（资讯正文 `fetch_info_detail`）；② `open_in_browser` 打开正文原文 | URL 可能被诱导/伪造，后端抓取有 **SSRF 面**，且须防钓鱼跳转；域名收紧不影响功能（资讯正文全在校园域内） |
| `is_http_url`（**协议白名单**，批次 3 新增） | 仅 `http` / `https` | `open_app` 打开校方应用目录下发的 `appLink` | appLink 来自校方应用目录（受信来源）、后端**不抓取**它（无 SSRF 面）、只在系统浏览器打开——实测 30 个应用中 **16 条链接在校园域外**（万方 4、虚拟图书馆 4、一卡通 `10.3.100.110` 4、超星泛雅 2、中国知网 2），域名限制只会拦掉学校自己的合法应用 |

一句话口径：**抓取动作按域名白名单，打开动作按协议白名单**；`open_app` 复用 `open_url_in_browser` 的打开方式（官方 `tauri-plugin-opener` Rust API），仅替换校验函数。

### H2 会议并入的数据源与周次构造

- **接口**：`GET api/uppexcard/ext/dynamicData/10.1.90.34/ZCHY?DJZ=<周次会议标题>&pageNum=1&pageSize=20`（门户信封 `meta.success`；`10.1.90.34` 为门户代理的内部主机）。
- **DJZ 必须带教学周次（实测四组对照）**：`第二周会议日程安排表`→6 条、`第一周…`→3 条、`第九周…`→0 条、无周次前缀→0 条。标题由 `meeting_query_title(week)` = `第<中文数字>周会议日程安排表` 构造（`week_to_chinese` 覆盖 1–99）；教学周次由区间起点与学期开学日推算（`teaching_week_of`，开学当周 = 第 1 周），开学前返回 None 走降级。
- **字段映射**：`HYMC`→标题、`DD`→地点、`ZCR`→主持人、`CBDW`→承办单位、`CXRY`→参会人员、`RQ`（如「9月15日」）+`NF`（年份）→日期、`SJ`（如「下午3:00」）→时间、`classifyCode` 固定 `Default-Meeting`（名称/色值由分类列表映射）。
- **时间解析与降级**：`SJ` 为自然语言——全角冒号归一、跳过前导非数字取段首数字、「下午/晚上」且 <12 加 12（「下午3:00」→15:00）；**解析不出按全天（00:00–23:59:59.999），解析出则 `endMs=startMs`**（服务端无结束时刻，不伪造）；`NF`/`RQ` 缺失或推不出日期的条目跳过。
- **降级承诺与可观测化**：并入在命令层 `get_schedule_month` 内完成，任一环节失败（codes 未选会议 / 学期信息失败 / 周次推算失败 / 拉取或解析失败 / 0 条）→ 空贡献，绝不影响课表日程与日历；会议按周次会话内缓存（0 条也缓存、失败不缓存）。每个失败点留一行 `[meeting-diag]` stderr（只含环节+周次+HTTP 状态+错误类别，不含凭据/响应体），成功路径零输出。

### H4 WebVPN 归 M4 的实测证据（不做 URL 包装的理由）

1. **网关对未登录请求一律回落**：会议代理端点无凭据 GET 实测返回 `302` → `Location: http://my.cwxu.edu.cn`（首页）；应用域名对未登录请求实测一律落 CAS 登录页。
2. **明文包装形式无法验证**：三种包装形式（`/http/<host>`、`/https/<host>`、内网 IP 直链）最终 URL **完全相同**——网关丢弃了目标路径，包装格式在没有 WebVPN 会话的前提下不可证真/伪。
3. **决策**：不写无法验证的推测实现；「WebVPN 会话打通 + URL 包装 + A 类 CAS 直达签发」整体归 **M4**（复用已验证的 WebVPN CAS 联动，届时按附录 A 的 A/B/C 分类接入打开策略引擎）。
