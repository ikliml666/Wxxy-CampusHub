## 三、缺口与补齐路线（P0 → P5，每项含上游证据 / 现状 / 验收）

### P0 课表样式对齐安卓端截图（用户点名，下一个任务）

**截图规格抽取**（上游 `CourseBlock.kt:66-90` + `ScheduleGridComponents.kt` 的默认渲染形态）：

1. **左侧时间列**：节次号（大字）+ 该节**起止时间两行**（如 `1` / `08:00` / `08:45`）。
2. **课程块三要素**：课程名（粗体、多行截断）→ **教师名** → `@教室`（@ 前缀拼接）。
3. **网格左上角**：`年份` + `当前周数` 角标（如 `2026` / `2周`）。
4. 列头 = 星期字 + 日期（`一` / `09-14`），今日列淡色高亮——**本仓已有**（`TimetablePanel.tsx:1121-1138`）。
5. 配色：浅底深字马卡龙色系——本仓 color-mix 14% 已接近，不动。

**现状差距**（已核实 `tauri-app/frontend/src/panels/TimetablePanel.tsx`）：

- 时间列只有大节号 + 开始时间（`:1146-1160`，缺结束时间）；
- 课程块只有课名 + 教室（`:1212-1225` 附近），**缺教师名**；
- 网格左上角空置（顶栏虽有「第N周/共M周」，等价信息已存在，角标属锦上添花）。

**粒度两案（实施时定，推荐 A）**：

- **方案 A（推荐，最像截图）**：网格改**按小节行**渲染（本校 10 小节），课程块跨小节合并。
  小节时间由大节时间推导：每大节 100min = 小节 45min + 间隔 10min + 小节 45min，即
  小节 `2k-1` = 大节 start .. start+45，小节 `2k` = 大节 start+55 .. 大节 end（与截图作息同构）。
  改动点：时间列渲染、`ceil(小节/2)` 的行定位反转（直接用小节坐标，反而更简单）；
  ICS / 今日页不受影响。
- **方案 B（最小 diff）**：保持大节行，时间列补结束时间 + 课程块加教师名。

**验收**：真机截图与上游安卓端对照（时间列/块三要素/今日高亮）；`tsc --noEmit` + `npm run build` + `cargo test --workspace` 全绿；契约文档补记（沿用 `docs/superpowers/plans/2026-09-18-m2.5-timetable.md` 的修订惯例）。

### P1 已迁字段接线：showWeekends / firstDayOfWeek

- 上游证据：清单 §1（约束联动 `firstDayOfWeek=周日 ⇒ showWeekends=true`）、§4（表头旋转 + 只渲染前 5 列）。
- 现状：模型与 TS 契约都有（`model.rs:76-84`、`types.ts:227,232`），前端**零消费**——
  `TimetablePanel.tsx:32` 硬编码 `["周一"…"周日"]` 七列。
- 做法：设置入口（课表页或全局设置）两个开关；列头/日期推算按 `firstDayOfWeek` 旋转；
  约束联动照抄上游。与 P0 同轮做最省（都动网格表头）。
- 验收：开关生效 + 约束联动 + 深色模式不破。

### P2 节假日 / 跳过日期（skippedDates）链路

- 上游证据：清单 §2.10（timor.tech API 拉整年假日）、§9（贯穿提醒/小组件/ICS/今日页）。
- 本仓适用面：今日页与课表页「放假那天不显示课」、ICS 导出跳过。
- **数据源两案**：上游用第三方 API（timor.tech）——本仓建议 **YAGNI 降级为手动维护**
  （课表页设置里加「跳过日期」多选，存 `CourseTableConfig`）；若将来要自动，可再评估 API（注意外发纪律）。
- 落点：`CourseTableConfig` 增 `skippedDates: Vec<NaiveDate>`（serde default 兼容旧文件）；
  `get_timetable` 组装视图时跳过；`build_ics` 跳过。
- 验收：标记某天放假后网格/ICS 均无该日课程；单测覆盖。

### P3 组合作息（冬/夏作息自动切换）

- 上游证据：清单 §3（专属/公共/组合三体系 + `alignTimeSlots` 节次对齐 + 日期区间规则）。
- 本仓现状：只有"专属"一种（`config.slots`）；换季要手动改两遍。
- 本仓为**单课表**，「公共作息（多表复用）」暂无意义——**最小集 = 组合作息**：
  `CourseTableConfig` 增 `slot_rules: Vec<{ start_date, end_date, slots }>`（按日期区间命中，
  `firstOrNull` 语义与上游一致）；生效取值收敛点仍是 `effective_slots`（三处共用不变式不破）。
  悬空区间（无命中）回落 `config.slots`。
- UI：作息弹层（`TimetablePanel.tsx` SlotsEditor）加「按日期生效的作息规则」区块。
- 验收：模拟两个区间（如 10-01 前后）自动切换；`cw status` 收尾照常。

### P4 拖拽改课（工作量最大，grid 内核已预留）

- 上游证据：清单 §6（长按编辑态/拖动/拉伸/跨周浮动搬运）、§16.2（**单周直改/多周克隆拆分**语义）。
- 桌面端鼠标拖拽比触摸简单（无长按歧义，按下即拖），跨周浮动搬运可先不做（YAGNI）。
- **关键设计决策（实施前冻结进契约）**：拖拽**导入课程**时怎么落库？
  - 上游直接改库——但本仓导入课程会被下次导入覆盖，且已有 override 模型；
  - **建议：拖拽导入课程 → 生成 `Rescheduled` override**（保留原数据、可撤销、不被导入冲掉，
    与调课通知同一条链路）；手动课程直接改字段。这与本仓模型自洽，优于上游。
- 复用：`grid.rs` 的 `time_to_grid_scale`/`grid_scale_to_time`（当初就是为此预留）。
- 验收：拖动改星期/节次 → override 生成 →「撤销」恢复；多周课拖拽只影响目标周
  （对照上游克隆拆分语义——在 override 模型下等价于 override 只记单周，已有 `newDay/newWeek` 字段承载）。
