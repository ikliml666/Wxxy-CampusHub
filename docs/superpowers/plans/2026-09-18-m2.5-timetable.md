## 1. 已实测事实（不必重测，可直接引用）

### 1.1 教务 SSO 链路（2026-09-18 实测，代码见 `crates/campus-auth/src/jwglxt.rs`）

- 教务在 CAS 注册的 service = `https://jwgl.cwxu.edu.cn/sso/lyiotlogin`（自引用回跳）
- **ST 与 service 绑定**：门户 ticket 直接拿去教务 = 404；必须用已有 TGT 换发教务 service 的 ST
- 换票：`POST {CAS_BASE}/v1/tickets/{tgt}`（form `service=<JWGL_SERVICE>`）→ **200 + 纯文本 `ST-…`**（非 JSON）
- 落地链（5 跳 302）：`/sso/lyiotlogin?ticket=ST` → `/jwglxt/ticketlogin?uid=…` → `/xtgl/login_slogin.html` → `/xtgl/index_initMenu.html?jsdm=xs`
- 教务会话 cookie：`route` + `JSESSIONID`（与门户 `customsid` 相互独立，同一 jar 并存）
- **CAS 不种任何登录 cookie** → 会话续期只能靠客户端保存的 TGT
- 现成函数：`CasClient::sso_ticket(tgt, service)`、`CasClient::jwglxt_sso(tgt)`

### 1.2 课表接口

- `POST https://jwgl.cwxu.edu.cn/jwglxt/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151`
  （`gnmkdm` 在 **query**；body 仅 `xnm=<学年起始年>&xqm=<3=第1学期/12=第2学期/16=暑期>`）
- 最小头组：仅 `Content-Type: application/x-www-form-urlencoded;charset=UTF-8`；
  **但必须带 `X-Requested-With: XMLHttpRequest`**——未登录时它让服务端返回 `901`，不带则返回 200 登录页 HTML（无法区分）
- 实测：本学年返回 8 条 `kbList`，字段与 `zhengfang::parse_kb_response` 映射**完全一致**，无需改解析器
- 参数推导口径（已定）：`xnm` = 门户 `SemesterInfo.start_date` 前 4 位；`xqm` = `semester` 的 `"1"→3 / "2"→12`
  （**不要用 `grade` 字段**：它是入学年级，对老生 ≠ 学年起始年）
- 失败模式：教务域无会话 + XRW → **HTTP 901**（空 body）；其他错误 → 见实现方实测补充

### 1.3 节次口径（与今日页同源）

- 教务 `jcs` 是**小节**号（如 `"3-4"`），校本作息是 **5 大节 × 2 小节**（大节 = 100 分钟）
- 大节时间（实测）：大节1 08:0?-…、大节2 **10:10-11:50**、大节3 **13:45-15:25**、大节4 **15:35-17:15**、大节5 …
- 映射：大节号 = `ceil(起始小节 / 2)`（`3-4节` → 大节 2 ✓ 与实测吻合）
- ⚠️ `campus-schedule::default_time_slots()` 是上游 13 节默认表（下午 14:00 起），**与本校不符**，
  它被 golden 测试钉住，**M2.5 不得修改它**；课表页一律走校本大节表
- 校本大节表现在是 `campus-portal::parse` 的**私有** `block_time_slots()`（`parse.rs:166`）。

`NoticeCandidate`：`{ noticeId, courseId?, courseName, changeType, weeks, newDay?, newStartSection?,
newEndSection?, newPosition?, confidence: "high"|"low", reason: String, excerpt: String }`

**命令返回一律套既有 `CommandResult{success, message?, data?}`**（`invokeCommand` 唯一出口已就位）。

### 2.4 自动更新的 diff 语义（冻结）

- 匹配键 = **课程名 + `class_id`（教务 `jxb_id`）**；`class_id` 缺失时退化为仅课程名匹配
- 新出现 → 新增（`source=Import`）；消失 → **置 `disabled=true`**，不删除；字段变化 → 只更新 `Import` 课程
- **`source=Manual` 的课程永不参与 diff，永不被打上 `disabled`**
- 本地手工编辑过的 `Import` 课程字段会被下一次导入覆盖（预期语义，不是 bug）

### 2.5 调课通知 L1/L2（冻结语义）

- 输入：通知正文 + 本地课程表；输出 `Vec<NoticeCandidate>`
- L1 规则层提取：课程名、周次（`第3周` / `3-4周` / `本周`）、星期（`周一`…`周日`）、
  节次（`3-4节` / `第3节`）、教室（`D4-207` 形态 / `教室：` 后）、关键词类型（调课/停课/补课）
- L2 置信：课程名**精确匹配**且周次、星期、节次齐全 → `high`（自动应用）；
  缺任一要素、或课程名匹配到多门 → `low`（进「待确认」列表，用户一键采纳）
- `noticeId`：本轮手动粘贴场景由实现方生成稳定 id（建议 `manual:<内容 sha256 前 16 位>`）；
  M5 接公告流时改用公告 id
- override 叠加于导入课程之上（原数据保留）；`revoke_notice` 按 `noticeId` 整批撤销

### 2.5.1 停课的渲染口径（2026-09-18 收尾轮定，原先未定义）

`OverrideKind::Cancelled` 的语义按 `new_day` 是否为空分两档：

| `new_day` | 语义 | 渲染 |
|---|---|---|
| `Some(d)` | 只停「该周 · 星期 d」那一次课 | 该周星期 d 的原时段显示虚线「已停」占位；本周其他星期的同课不受影响 |
| `None` | 通知没说停哪一天 → **该课程在 `weeks` 列出的周次内整周全停** | 该周内该课**所有**原时段都显示虚线「已停」占位 |

解析侧（`notice.rs`）保持既有行为：通知里提到星期就填进 `new_day`，没提就留 `None`。
`new_start_section`/`new_end_section`/`new_position` 对停课无意义（保留原值或 `None` 均可，渲染层忽略）。

### 7.1 新命令 `save_semester_config`

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `save_semester_config` | `SemesterConfigInput` | `TimetableView` | 返回刷新视图，沿 `save_time_slots` 惯例（前端免二次拉取） |

`SemesterConfigInput`（serde camelCase，容器级 `#[serde(default)]`，缺省字段容忍旧调用方）：

`{ semesterStartDate: string | null, semesterTotalWeeks: number, firstDayOfWeek: number, showWeekends: boolean, currentWeekHint?: number | null }`

语义：

- `semesterStartDate = null` = 清空开学日（假期态）；
- `currentWeekHint` 有值时**由后端**用 `weeks::semester_start_from_week(today, hint, firstDayOfWeek)`
  反推开学日并覆盖入参 start_date（反推口径单点在后端，前端不自算）；
- 校验（非法返回中文错误）：`semesterTotalWeeks ∈ 1..=30`（上游滚轮范围）、
  `firstDayOfWeek ∈ 1..=7`、`currentWeekHint ∈ 1..=semesterTotalWeeks`。

### 7.2 显示约束联动（后端单点 `apply_display_constraints`）

`first_day_of_week == 7 ⇒ show_weekends = true`；`!show_weekends ⇒ first_day_of_week = 1`
（上游双向联动）。收口在后端 save 路径单点执行；前端只做联动提示、不禁用控件
（两处开关各自联动必漏，故不收前端）。

### 7.3 ICS 周首日对齐公式

```
week_first = previous_or_same_day_of_week(semester_start_date, first_day_of_week)
col        = (day - first_day_of_week + 7) % 7
date       = week_first + (week - 1) * 7 + col
```

`first_day_of_week = 1` 且开学日为周一时与旧公式（`start + (week-1)*7 + day-1`）逐字节
等价（既有 golden 测试保持不变）。

### 7.4 `campus_schedule` 导出面扩动

`weeks::previous_or_same_day_of_week` 改 `pub` 并由 crate 根 re-export；前端 `weekDates`
的 JS 镜像（`previousOrSame`）语义锚定该函数，两处注释互锚、改一处必须同步另一处。

### 8.4 `campus_schedule::occurrence` 公开结构（决策 5，新模块）

```rust

pub struct CourseOccurrence {
    pub kind: OccurrenceKind,
    pub day: u8,
    /// 节次（教务小节口径，与 Course.start_section 同尺度）；None 仅当课程本身
    /// custom（is_custom_time 且无节次）——消费方（ICS/今日页）按 custom 时刻取值

    pub end_section: Option<u8>,
    pub position: String,
    /// 产生本实例的 override id；普通原位实例为 None。供 ICS DESCRIPTION 追加
    /// 「调课/补课」标注与批 9 今日页溯源（决策 5 结构规格之外的最小补充，
    /// 理由：Solid 实例无法仅凭几何字段区分「原位」与「调课新位/补课」）。
    pub source_override_id: Option<String>,
}
/// 课程在某周经 override 展开后的全部实例（含 ghost 供前端语义对照；
/// ICS/今日页只消费 Solid）。语义必须与前端 buildWeekBlocks 对齐，
/// 两处注释互锚：改一处必须同步另一处。
pub fn expand_occurrences(course: &Course, overrides: &[CourseOverride], week: u32) -> Vec<CourseOccurrence>
```

展开语义（逐分支对照前端 `buildWeekBlocks`，`TimetablePanel.tsx`）：

- `course.disabled` 或 `week` 不在 `course.weeks` → 空列表；
- **停课两档**（契约 §2.5.1）：cancelled override `new_day = None` → 该课该周全部原时段
  `Cancelled`；`new_day = Some(d)` → 仅 `d == course.day` 时该原时段 `Cancelled`（否则该 override
  对本课不生效）；
- **调课**：rescheduled override 且新时间 ≠ 原时间 → 原时段 `MovedOut` + 新时段 `Solid`
  （节次取 `new_start_section`/`new_end_section`，后者缺省 = 起始；教室取 `new_position` 缺省原教室）；
- **仅换教室**（新时间 = 原时间）→ 原位单条 `Solid`，教室取 `new_position`；
- **补课**：extra override → 新增一条 `Solid` 实体（day 取 `new_day` 缺省原 day；节次缺省第 1 小节起）；
- **多条 override 叠加**：逆序取最后一条匹配（后采纳覆盖先采纳）；**停课优先于调课**
  （cancel 命中即短路实体块分支，不再看 resched）；**extra 补课独立于以上所有分支**
  （停课/调课周同时补课 → ghost/移位实例与补课实例并存；补课周可以不属于
  `course.weeks`——复核 P1-a/P1-b 修订，与前端 extra 循环同语义）；
- **custom 课 override 语义（复核 P3-c 登记，与 occurrence.rs 模块注释互锚）**：
  custom 课（`start_section`/`end_section` 为 None）不进网格（前端 `buildWeekBlocks`
  对节次 None 的课程 continue 跳过）；被 resched 时 occurrence 产出带节次的 Solid
  （新节次取 override 的 new_*），消费方走大节表取时刻，不用 custom 时刻；未被
  调整时产出节次 None 的 Solid，消费方按 `custom_*_time` 取时刻。批 9 今日页
  统一本口径。

### 8.5 ICS 映射规则（决策 5）

- 每门未 `disabled` 课程 × 其每个教学周（周次集合 = `course.weeks ∪ 各 override.weeks`
  去重排序，复核 P1-b 修订：补课周可不属于 course.weeks）调 `expand_occurrences`，
  **只消费 `Solid`**；
- 每个 VEVENT 日期命中 `config.skipped_dates` → 跳过；
- 时刻取值：节次课查**该日** `effective_slots_at`（大节 = `(s+1)/2` 不变，查不到 → 跳过该实例）；
  **custom 课（节次为 None）DTSTART/DTEND 直接取 `custom_start_time`/`custom_end_time`**
  （缺失 → 跳过该实例）；
- UID（复核 P3-a 修订）：`{courseId}-w{week}d{day}s{startSection}@campushub`——
  原位实例（含仅换教室）与旧版逐字节一致（golden 保）；**调课新位与补课实例追加
  `-o{override_id 前 8 位}` 后缀**，防同周同日同起始小节与原位 UID 逐字节相撞；
  custom 课（无节次）用 `scustom` 段替代 `s{startSection}`；
- DESCRIPTION：追加「调课」（rescheduled 来源的 Solid）/「补课」（extra 来源）；
- VTIMEZONE 维持 floating local time（无 TZID/Z），不引入 VTIMEZONE 块；
- 周首日对齐沿用契约 §7.3 公式。无 override / 无 skippedDates 的课表导出与旧版逐字节一致。

## 9. 批 3 修订（2026-09-19，P3 组合作息）

### 9.1 数据模型：`SlotRule` 与 `CourseTableConfig.slot_rules`

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct SlotRule {
    /// 生效起始日期（含）
    pub start_date: NaiveDate,
    /// 生效结束日期（含）
    pub end_date: NaiveDate,
    /// 该区间的作息（恒非空，保存时校验）
    pub slots: Vec<TimeSlot>,
}
```

`CourseTableConfig` 增 `#[serde(default)] pub slot_rules: Vec<SlotRule>`
（序列化 `slotRules: [{ startDate, endDate, slots }]`）。
旧 `timetable.json` 无该键 → 空列表。

### 9.2 `effective_slots_at` 区间命中（三段回落链）

命中语义（对齐上游 firstOrNull）：`start_date <= date <= end_date`（**含端点**）取
**首个命中**；区间允许重叠（重叠取**先声明**者，上游同语义，单测钉死）。回落链：

1. `slot_rules` 首个日期命中的规则（其 `slots` 恒非空）；
2. 无命中 → `config.slots`（有值且非空）；
3. 仍无 → 内置 `campus_portal::block_time_slots()`。

签名不变（§8.3 已迁移），只改函数内部；三处共用收敛点不变：网格
（`TimetableView.slots`）、ICS 展开（逐 VEVENT 日期取值）、大节号→时刻查找。

### 9.3 新命令 `save_slot_rules`

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `save_slot_rules` | `rules: SlotRule[] \| null` | `TimetableView` | **整体替换**语义；`null` = 清空全部规则；返回刷新视图 |

校验（`validate_slot_rules`）：每条规则 `start_date <= end_date`、`slots` 非空、
且每条规则内部复用 `validate_time_slots`（§2.3 收尾轮口径）；非法一律中文报错不落库。

### 9.4 `TimetableView.slots` 取「今天」的生效作息

网格行数按单份 slots 渲染，跨作息区间的换季周无法逐天变行——`build_timetable_view`
传**今天**取生效作息（与上游周视图同口径的已知取舍，注释写明）；ICS 精确到每个
VEVENT 日期逐日取值。前端 SlotsEditor 增「按日期生效的作息规则」区块（起止 date
input + 作息行编辑 + 删除 + 新增规则；主作息区块保留作回落用途）。
