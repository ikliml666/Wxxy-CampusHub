## 1. 已实测事实（不必重测，可直接引用）

### 1.1 教务 SSO 链路（2026-09-18 实测，代码见 `crates/campus-auth/src/jwglxt.rs`）

- 教务在 CAS 注册的 service = `https://jwgl.cwxu.edu.cn/sso/lyiotlogin`（自引用回跳）
- **ST 与 service 绑定**：门户 ticket 直接拿去教务 = 404；必须用已有 TGT 换发教务 service 的 ST
- 换票：`POST {CAS_BASE}/v1/tickets/{tgt}`（form `service=<JWGL_SERVICE>`）→ **200 + 纯文本 `ST-…`**（非 JSON）
- 落地链（5 跳 302）：`/sso/lyiotlogin?ticket=ST` → `/jwglxt/ticketlogin?uid=…` → `/xtgl/login_slogin.html` → `/xtgl/index_initMenu.html?jsdm=xs`
- 教务会话 cookie：`route` + `JSESSIONID`（与门户 `customsid` 相互独立，同一 jar 并存）
- **CAS 不种任何登录 cookie** → 会话续期只能靠客户端保存的 TGT
- 现成函数：`CasClient::sso_ticket(tgt, service)`、`CasClient::jwglxt_sso(tgt)`

### 1.2 课表接口

- `POST https://jwgl.cwxu.edu.cn/jwglxt/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151`
  （`gnmkdm` 在 **query**；body 仅 `xnm=<学年起始年>&xqm=<3=第1学期/12=第2学期/16=暑期>`）
- 最小头组：仅 `Content-Type: application/x-www-form-urlencoded;charset=UTF-8`；
  **但必须带 `X-Requested-With: XMLHttpRequest`**——未登录时它让服务端返回 `901`，不带则返回 200 登录页 HTML（无法区分）
- 实测：本学年返回 8 条 `kbList`，字段与 `zhengfang::parse_kb_response` 映射**完全一致**，无需改解析器
- 参数推导口径（已定）：`xnm` = 门户 `SemesterInfo.start_date` 前 4 位；`xqm` = `semester` 的 `"1"→3 / "2"→12`
  （**不要用 `grade` 字段**：它是入学年级，对老生 ≠ 学年起始年）
- 失败模式：教务域无会话 + XRW → **HTTP 901**（空 body）；其他错误 → 见实现方实测补充

### 1.3 节次口径（与今日页同源）

- 教务 `jcs` 是**小节**号（如 `"3-4"`），校本作息是 **5 大节 × 2 小节**（大节 = 100 分钟）
- 大节时间（实测）：大节1 08:0?-…、大节2 **10:10-11:50**、大节3 **13:45-15:25**、大节4 **15:35-17:15**、大节5 …
- 映射：大节号 = `ceil(起始小节 / 2)`（`3-4节` → 大节 2 ✓ 与实测吻合）
- ⚠️ `campus-schedule::default_time_slots()` 是上游 13 节默认表（下午 14:00 起），**与本校不符**，
  它被 golden 测试钉住，**M2.5 不得修改它**；课表页一律走校本大节表
- 校本大节表现在是 `campus-portal::parse` 的**私有** `block_time_slots()`（`parse.rs:166`）。

### 2.4 自动更新的 diff 语义（冻结）

- 匹配键 = **课程名 + `class_id`（教务 `jxb_id`）**；`class_id` 缺失时退化为仅课程名匹配
- 新出现 → 新增（`source=Import`）；消失 → **置 `disabled=true`**，不删除；字段变化 → 只更新 `Import` 课程
- **`source=Manual` 的课程永不参与 diff，永不被打上 `disabled`**
- 本地手工编辑过的 `Import` 课程字段会被下一次导入覆盖（预期语义，不是 bug）

### 2.5 调课通知 L1/L2（冻结语义）

- 输入：通知正文 + 本地课程表；输出 `Vec<NoticeCandidate>`
- L1 规则层提取：课程名、周次（`第3周` / `3-4周` / `本周`）、星期（`周一`…`周日`）、
  节次（`3-4节` / `第3节`）、教室（`D4-207` 形态 / `教室：` 后）、关键词类型（调课/停课/补课）
- L2 置信：课程名**精确匹配**且周次、星期、节次齐全 → `high`（自动应用）；
  缺任一要素、或课程名匹配到多门 → `low`（进「待确认」列表，用户一键采纳）
- `noticeId`：本轮手动粘贴场景由实现方生成稳定 id（建议 `manual:<内容 sha256 前 16 位>`）；
  M5 接公告流时改用公告 id
- override 叠加于导入课程之上（原数据保留）；`revoke_notice` 按 `noticeId` 整批撤销

### 2.5.1 停课的渲染口径（2026-09-18 收尾轮定，原先未定义）

`OverrideKind::Cancelled` 的语义按 `new_day` 是否为空分两档：

| `new_day` | 语义 | 渲染 |
|---|---|---|
| `Some(d)` | 只停「该周 · 星期 d」那一次课 | 该周星期 d 的原时段显示虚线「已停」占位；本周其他星期的同课不受影响 |
| `None` | 通知没说停哪一天 → **该课程在 `weeks` 列出的周次内整周全停** | 该周内该课**所有**原时段都显示虚线「已停」占位 |

解析侧（`notice.rs`）保持既有行为：通知里提到星期就填进 `new_day`，没提就留 `None`。
`new_start_section`/`new_end_section`/`new_position` 对停课无意义（保留原值或 `None` 均可，渲染层忽略）。

### 7.1 新命令 `save_semester_config`

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `save_semester_config` | `SemesterConfigInput` | `TimetableView` | 返回刷新视图，沿 `save_time_slots` 惯例（前端免二次拉取） |

`SemesterConfigInput`（serde camelCase，容器级 `#[serde(default)]`，缺省字段容忍旧调用方）：

`{ semesterStartDate: string | null, semesterTotalWeeks: number, firstDayOfWeek: number, showWeekends: boolean, currentWeekHint?: number | null }`

语义：

- `semesterStartDate = null` = 清空开学日（假期态）；
- `currentWeekHint` 有值时**由后端**用 `weeks::semester_start_from_week(today, hint, firstDayOfWeek)`
  反推开学日并覆盖入参 start_date（反推口径单点在后端，前端不自算）；
- 校验（非法返回中文错误）：`semesterTotalWeeks ∈ 1..=30`（上游滚轮范围）、
  `firstDayOfWeek ∈ 1..=7`、`currentWeekHint ∈ 1..=semesterTotalWeeks`。

### 7.2 显示约束联动（后端单点 `apply_display_constraints`）

`first_day_of_week == 7 ⇒ show_weekends = true`；`!show_weekends ⇒ first_day_of_week = 1`
（上游双向联动）。收口在后端 save 路径单点执行；前端只做联动提示、不禁用控件
（两处开关各自联动必漏，故不收前端）。

### 7.3 ICS 周首日对齐公式

```
week_first = previous_or_same_day_of_week(semester_start_date, first_day_of_week)
col        = (day - first_day_of_week + 7) % 7
date       = week_first + (week - 1) * 7 + col
```

`first_day_of_week = 1` 且开学日为周一时与旧公式（`start + (week-1)*7 + day-1`）逐字节
等价（既有 golden 测试保持不变）。

### 7.4 `campus_schedule` 导出面扩动

`weeks::previous_or_same_day_of_week` 改 `pub` 并由 crate 根 re-export；前端 `weekDates`
的 JS 镜像（`previousOrSame`）语义锚定该函数，两处注释互锚、改一处必须同步另一处。

### 8.4 `campus_schedule::occurrence` 公开结构（决策 5，新模块）

```rust

pub struct CourseOccurrence {
    pub kind: OccurrenceKind,
    pub day: u8,
    /// 节次（教务小节口径，与 Course.start_section 同尺度）；None 仅当课程本身

    pub end_section: Option<u8>,
    pub position: String,
    /// 产生本实例的 override id；普通原位实例为 None。供 ICS DESCRIPTION 追加
    /// 「调课/补课」标注与批 9 今日页溯源（决策 5 结构规格之外的最小补充，
    /// 理由：Solid 实例无法仅凭几何字段区分「原位」与「调课新位/补课」）。
    pub source_override_id: Option<String>,

/// 课程在某周经 override 展开后的全部实例（含 ghost 供前端语义对照；
/// ICS/今日页只消费 Solid）。语义必须与前端 buildWeekBlocks 对齐，
/// 两处注释互锚：改一处必须同步另一处。
pub fn expand_occurrences(course: &Course, overrides: &[CourseOverride], week: u32) -> Vec<CourseOccurrence>
```

展开语义（逐分支对照前端 `buildWeekBlocks`，`TimetablePanel.tsx`）：

- `course.disabled` 或 `week` 不在 `course.weeks` → 空列表；
- **停课两档**（契约 §2.5.1）：cancelled override `new_day = None` → 该课该周全部原时段
  `Cancelled`；`new_day = Some(d)` → 仅 `d == course.day` 时该原时段 `Cancelled`（否则该 override
  对本课不生效）；
- **调课**：rescheduled override 且新时间 ≠ 原时间 → 原时段 `MovedOut` + 新时段 `Solid`
  （节次取 `new_start_section`/`new_end_section`，后者缺省 = 起始；教室取 `new_position` 缺省原教室）；
- **仅换教室**（新时间 = 原时间）→ 原位单条 `Solid`，教室取 `new_position`；
- **补课**：extra override → 新增一条 `Solid` 实体（day 取 `new_day` 缺省原 day；节次缺省第 1 小节起）；
- **多条 override 叠加**：逆序取最后一条匹配（后采纳覆盖先采纳）；**停课优先于调课**
  （cancel 命中即短路实体块分支，不再看 resched）；**extra 补课独立于以上所有分支**
  （停课/调课周同时补课 → ghost/移位实例与补课实例并存；补课周可以不属于
  `course.weeks`——复核 P1-a/P1-b 修订，与前端 extra 循环同语义）；
- **custom 课 override 语义（复核 P3-c 登记，与 occurrence.rs 模块注释互锚）**：
  custom 课（`start_section`/`end_section` 为 None）不进网格（前端 `buildWeekBlocks`
  对节次 None 的课程 continue 跳过）；被 resched 时 occurrence 产出带节次的 Solid
  （新节次取 override 的 new_*），消费方走大节表取时刻，不用 custom 时刻；未被
  调整时产出节次 None 的 Solid，消费方按 `custom_*_time` 取时刻。批 9 今日页
  统一本口径。

### 8.5 ICS 映射规则（决策 5）

- 每门未 `disabled` 课程 × 其每个教学周（周次集合 = `course.weeks ∪ 各 override.weeks`
  去重排序，复核 P1-b 修订：补课周可不属于 course.weeks）调 `expand_occurrences`，
  **只消费 `Solid`**；
- 每个 VEVENT 日期命中 `config.skipped_dates` → 跳过；
- 时刻取值：节次课查**该日** `effective_slots_at`（大节 = `(s+1)/2` 不变，查不到 → 跳过该实例）；
  **custom 课（节次为 None）DTSTART/DTEND 直接取 `custom_start_time`/`custom_end_time`**
  （缺失 → 跳过该实例）；
- UID（复核 P3-a 修订）：`{courseId}-w{week}d{day}s{startSection}@campushub`——
  原位实例（含仅换教室）与旧版逐字节一致（golden 保）；**调课新位与补课实例追加
  `-o{override_id 前 8 位}` 后缀**，防同周同日同起始小节与原位 UID 逐字节相撞；
  custom 课（无节次）用 `scustom` 段替代 `s{startSection}`；
- DESCRIPTION：追加「调课」（rescheduled 来源的 Solid）/「补课」（extra 来源）；
- VTIMEZONE 维持 floating local time（无 TZID/Z），不引入 VTIMEZONE 块；
- 周首日对齐沿用契约 §7.3 公式。无 override / 无 skippedDates 的课表导出与旧版逐字节一致。

## 10. 批 4 修订（2026-09-19，P4 网格拖拽改课）

> 蓝图：`docs/superpowers/plans/2026-09-19-timetable-p1-p5.md` 架构决策 4 + 批 4。
> **零新命令、零后端改动**：纯前端复用 `apply_override`（override 路径）与
> `update_course`（直改路径），§2.3 命令表不变。以下新增面冻结。

### 10.1 点击/拖拽区分（pointer 交互）

`pointerdown` 记录起点；移动曼哈顿距离 > **4px** 进入拖拽（`setPointerCapture`）；
`pointerup` 时未进入拖拽 → 原点击行为（详情浮层）。**进入过拖拽后必须以 suppress
标志位吃掉后续 click 事件**（pointer capture 后 click 仍触发）。Esc 取消拖拽复位
（同样置 suppress 吃掉随后的 click）。

### 10.2 落点计算：纯前端几何，不走 grid.rs 互转

`grid.rs` 的 `time_to_grid_scale`/`grid_scale_to_time` 是「时刻 ↔ 浮点网格」换算
（24h 模式预留件），与大节行网格无关，本批不使用、保留不动：

```
目标大节 = clamp(floor((y - 网格顶) / ROW_H) + 1, 1, slots.length - 原跨度)
显示列   = 命中的天列（按列 rect 命中测试；超出网格边缘 clamp 到首/末列）
实际星期 = displayDayOf(显示列)   // 批 1 的 (firstDay - 1 + i) % 7 + 1 反映射，
                                  // firstDay=7 时第 0 列 = 周日，showWeekends=false
                                  // 时只有 5 列 rect，方向天然正确
```

起始大节按「末位对齐」clamp（整块不许超出作息行数）；落点为跳过日期列（§8.1）
时视为无效落点（拖拽取消回弹）。

### 10.3 拖拽预览

原块 `opacity-40`；目标位置按**原跨度**画虚线 ghost div；落点列高亮。拖主体不改
时长；**拉伸手柄不做**；跨周边缘浮动搬运不做。ghost 块（cancelled / moved-out）
与 extra 补课块**不可拖**（点击详情照旧）。

### 10.4 落库分叉（冻结）

拖拽落点 =（新星期 d，新起始大节 k）。换算（Course 小节口径）：

```
newStartSection = 2*k - 1
newEndSection   = newStartSection + (原课程 endSection - 原课程 startSection)
                  // 跨度按课程原始小节差保持（2026-09-19 交叉复核订正：非大节差，
                  // 如 3-4 节拖到第 3 大节 → 5-6；custom 课无小节本就不渲染块、不可拖）
newPosition     = 拖拽块的当前显示教室（保持教室不变；通知已改教室则保持新教室）
```

按**课程**精确分叉（对展示周 week）：

| 条件 | 路径 | 语义 |
|---|---|---|
| `weeks.length > 1`（无论来源） | `apply_override`，单周 Rescheduled override | `weeks = [展示周]`、`newDay/newStartSection/newEndSection`、`newPosition`、`sourceNoticeId = "drag:<courseId>:<week>"`、`confidence = "low"`、`reason = "拖拽调整"`、`excerpt = ""` |
| `weeks.length === 1 && source === "import"` | 同上走 override | 不直改——导入课直改字段会被下次导入覆盖（§2.4），override 模型下不被触碰 |
| `weeks.length === 1 && source === "manual"` | `update_course` 直改字段 | 本就只有这一周；直改前 revoke 该课挂在本周的 rescheduled override（否则残留 override 与直改冲突再次移位） |

- `drag:` 来源 id 的幂等覆盖：`upsert_override` 幂等键 = `source_notice_id +
  course_id`（§2.3 实现），`drag:<courseId>:<week>` 含 courseId 且按周区分 →
  同课同周反复拖拽自然覆盖为最后位置；不同周的 drag override 并存、可单独撤销。
- **位置未变短路**：落点 day 与起始大节均等于拖拽块当前位置 → 不产生任何记录。
- 调整列表对 `sourceNoticeId` 以 `drag:` 开头的 override 显示「拖拽」来源标签，
  撤销按钮复用 `revoke_notice`（撤单条）。

### 13.1 `TimetableView.week_state`（顶栏标题态机）

|---|---|

## 14. 批 8 修订（2026-09-19，P5-d 调课搬迁与快速删除）

> 蓝图：`docs/superpowers/plans/2026-09-19-timetable-p1-p5.md` 批 8 + 风险 R8。
> 以下新增面冻结；既有 §1–§13 段落不变。

### 14.1 新命令 `move_day_courses`（调课搬迁，单模式「移动」）

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `move_day_courses` | `fromDate: string, toDate: string`（`"YYYY-MM-DD"`，NaiveDate） | `MoveResult` | 把源日期当天的全部未停开课程整批搬到目标日期 |

`MoveResult`：`{ moved: u32, noticeId: string }`——`moved` = 本次生成/覆盖的搬迁
override 数（= 移动的课程数）；`noticeId` = 整批撤销句柄，`revoke_notice(noticeId)`
一次撤销本批全部搬迁。

语义（风险 R8 冻结口径）：

- 源/目标日期各自经 `weeks::week_index_at_date(date, start, firstDay)`（**对齐
  周首日**，禁用 epoch 直除——上游三处口径不一致的坑）算出
  `(教学周, 星期)`；星期 = 日期的 ISO 星期号（1=周一…7=周日）。
- 校验（非法中文报错不落库）：未设开学日 → 「尚未设置学期开学日」；
  `fromDate == toDate` → 「源日期与目标日期不能相同」；任一日期周次越界
  （`< 1` 或 `> semester_total_weeks`）→ 「不在学期周次范围内」。
- 对「源 (week, day) 有课」的每门**未 disabled** 课程（判定 =
  `course.day == 源星期 && course.weeks 含源周`）生成一条 Rescheduled override：
  `weeks = [目标周]`、`new_day = 目标星期`、节次取课程原值（custom 课为
  None，透传）、`new_position = course.position` 原值（空串取 `null`）。
- **统一走 override（含手动课）**：整批可经既有 `revoke_notice` 一次撤销；
  同批统一 `source_notice_id = "move:<fromDate>:<toDate>"`，重跑经
  `upsert_override`（幂等键 = noticeId + courseId）覆盖为最后状态，与 drag
  同链路；已存在的其他 override（如 drag）不清理——叠加渲染按「逆序取最后」
  语义，后写入的搬迁记录自然生效。
- 教室简化取舍（冻结）：取 `course.position` 原值，不解析「源周源日生效
  时刻的调课教室」（需展开 override 链，复杂度不成比例）。
- 调整列表对 `sourceNoticeId` 以 `move:` 开头的 override 显示「搬迁」来源
  标签（同 `drag:` → 「拖拽」惯例），撤销按钮复用 `revoke_notice`。

### 14.2 新命令 `quick_delete`（快速删除，周次 × 星期）

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `quick_delete` | `weeks: number[], days: number[]` | `u32` | 受影响课程数（删空整删与部分移除均计 1 门） |

语义：

- 对每门课（**导入 / 手动 / disabled 都可清**，无 disabled 过滤）：若
  `course.day ∈ days`，从 `course.weeks` 移除选中周次的命中项。
- **weeks 删空 → 删除整条课程**（本仓无关联表，空 weeks 僵尸记录不如删净），
  删除时级联清理该课挂载的全部 override（同 `delete_course` 链路）。
- 仅删部分周次时残留 override **不清理**：其 `weeks` 不含被删周即不生效
  （渲染与 ICS 均按 `course.weeks`/`override.weeks` 交集判定），无害。
- 日期区间第二维度不做（蓝图 YAGNI）。
- 校验（非法中文报错不落库）：`weeks` 或 `days` 为空 → 「请先选择要删除的
  周次与星期」；`days` 含 1..=7 之外 → 「星期必须在周一至周日之间」；
  越界周次（> 总周数）不报错、自然忽略（无课程周次命中）。

### 14.3 前端（设置弹层「批量调整」区块，`types.ts` 镜像）

- `SettingsEditor`（课表设置弹层）跳过日期区块之下新增「批量调整」区块：
  - **搬迁**：两个 `<input type="date">`（源/目标）+ 执行按钮；执行前
    `window.confirm("将把 X 的全部课程移动到 Y …可整批撤销")`。
  - **快速删除**：周次多选 chips（1..totalWeeks）+ 星期多选 chips（周一..周日）
    + 确认按钮；confirm 文案列受影响课程数（前端按 `tt.courses` 本地计算预览：
    `c.day ∈ days && c.weeks 命中选中周`）。
- `types.ts` 增 `MoveResult { moved: number; noticeId: string }`。
- 执行成功后经 `reloadTick` 重拉课表；搬迁结果提示整批撤销入口（「已生效
  调整」列表）。

## 15. 批 9 修订（2026-09-19，P5-e 今日页接本地课表）

> 蓝图：`docs/superpowers/plans/2026-09-19-timetable-p1-p5.md` 批 9 + 架构决策 3 + 风险 R9。
> 以下新增面冻结；既有 §1–§14 段落不变。

### 15.1 新命令 `get_today_courses`

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `get_today_courses` | 无 | `TodayCoursesView` | 本地课表的今日视图（纯函数 `today_courses(tt, now)` 产出，`now` = 命令层传入的本机 `Local::now().naive_local()`——时钟口径单点在后端）；独立命令，**不**混入 `get_timetable` / `get_portal_overview`（分层不污染） |

```rust
pub struct TodayCoursesView {
    pub date: String,               // "YYYY-MM-DD"
    pub current_week: Option<u32>,
    pub state: String,              // "normal" | "no_semester" | "vacation" | "skipped"
    pub has_local: bool,            // 本地课表已导入且有课程
    pub courses: Vec<TodayCourse>,  // 按开始时刻升序；停课实例不进列表
    pub next: Option<TodayCourse>,  // 第一门未结束的课程
}
pub struct TodayCourse {
    pub course_id: String, pub name: String, pub room: String, pub teacher: String,
    pub start_hm: String, pub end_hm: String,  // "HH:MM"
    pub ongoing: bool,                            // 后端按 now 算好
}
```

（serde camelCase：`currentWeek` / `hasLocal` / `courseId` / `startHm` / `endHm`。）

### 15.2 判定口径（冻结）

- **state 枚举**：`semester_start_date` 为 None → `no_semester`；有开学日但
  `current_week(today, cfg)` 越界（None）→ `vacation`；today 命中
  `config.skipped_dates` → `skipped`；其余 → `normal`（三态判定顺序即此优先级，
  越界日的 skipped 无意义）。非 normal 态 `courses` 恒为空、`next` 恒为 None。
- **has_local 口径**：`!courses.is_empty() && semester_start_date.is_some()`
  ——课程数 > 0 **且**已设开学日，两者都满足才信任本地。
- **课程展开**：normal 态对每门未 `disabled` 课程经 `expand_occurrences` 取本周
  实体（**只消费 Solid**——停课/调出 ghost 不进今日页，与 ICS 同语义），
  过滤 `occ.day == 今天星期`；时刻取值与 `build_ics` 同口径（契约 §8.5）：
  节次课查 `effective_slots_at(config, today)`（大节 = `(s+1)/2`，起/止任一查
  不到 → 该实例不进列表）；custom 课（节次 None）取 `custom_start_time`/
  `custom_end_time`（缺失 → 不进列表）。
- **next / ongoing**：以分钟粒度比较（`HH:MM` → 分钟数）。**「未结束」=
  `end > now`**；`next` = 升序序列中第一门未结束的课程，全部已结束 → None。
  **ongoing = `start <= now < end`**（恰在开始时刻 = 进行中；恰在结束时刻 =
  已结束，与「未结束」口径自洽）。前端不自算时钟。
- **本地优先 / 教务兜底**：前端 `has_local == true` → 「下一节课」横幅与新增
  「今日课程」列表用本地结果（`next` 为 null 如实显示今日无课/已结束）；
  `has_local == false` → 现状门户 `nextCourse` 展示**零变化**。理由：本地是
  教务数据的超集（叠加 override/停开/手动/跳过日），「下一节课」的价值在
  准确反映调整（决策 3）。
- **前端取数（风险 R9）**：authed 时 `get_portal_overview` 与 `get_today_courses`
  **并行**发起，各自 alive 标志、互不阻塞、各自四态（loading/ready/error/游客
  空态）；本地取数失败回落门户路径。`state == "skipped"` → 显示「今日放假」，
  `vacation` → 「假期中」，`no_semester` → 回落门户现状（`has_local` 此时必为
  false，同一路径）。今日课程列表每行「HH:MM-HH:MM 课名 @教室」；ongoing 高亮、
  已结束置灰（已结束 = 位于 `next` 之前的行，`next` 为 null 则全部已结束——
  前端由列表与 next 的相对位置推导，不读时钟）；不做时间轴刻度。
- `types.ts` 镜像 `TodayCourse` / `TodayCoursesView`。

- 收集/去重/排序/截断收敛在纯函数 `parse::collect_schedule_notices`：按 url
  去重（保留先出现条目）、按日期倒序（`publishTime` 字典序即时间序）、上限 20。
- 返回 `ScheduleNoticeBrief { title, date, url, column, matchedKeywords }`
  （camelCase）；任一栏目取数失败（未登录/网络）→ 中文报错透传。

### 18.3 公告正文解析：`parse_notice_from_url(url) -> Vec<NoticeCandidate>`

- 链路：`fetch_info_detail(url)`（域名白名单在其内强制）→ `article::html_text`
  剥标签取纯文本（块级标签转换行，script/style 剔除）→ 复用
  `parse_notice_text(text, &courses, current_week)`。
- 返回结构与现有 `parse_notice` 完全一致（候选列表，confidence/reason 在候选内）。
- **语义红线：解析结果只进候选确认流，不自动 apply**——采纳仍走
  `apply_override`，由用户确认，不静默改数据。`needsBrowser` 正文 / 空正文 →
  中文报错引导粘贴解析。
- 两命令均已注册 `lib.rs`。

### 18.4 测试口径

  1-2/3-4/5-6/7-8）在 11 小节表下时刻与旧大节表逐字节同值，golden 断言不变；
  custom slots / slot_rules 场景改用小节口径规则表断言。

## 20. 同步覆盖修复轮修订（2026-09-19，diff 匹配键 + 日期置换解析）

### 20.1 diff 匹配键加时段（修「同步后课程块被压缩」）

- **根因**：正方 kbList 对同一教学班（同 `jxb_id`）按多时段拆多条记录（实测：
  马原 3 条同 `540B1687E8…`、信安 2 条同 `542D71F5B2…`）。旧 match_key
  `(name, class_id)` 在二次同步时对同键多条做 `iter().find` 一对多命中——
  本地 3 条马原全部被覆盖成同一条教务记录的时段（周一 5-6），同格重叠 →
  前端分列渲染把课程块压缩成 1/3 宽（真机截图证实）。
- **修复**（`campus-schedule/src/diff.rs`）：match_key 扩为
  `(name, class_id, day, start_section, end_section)` 五元组；`diff_courses`
  改**消费式一对一配对**——incoming 按 key 分桶成 `HashMap<key, VecDeque<idx>>`，
  旧库逐条从对应队列队首消费（`consumed` 标记）；新增分支只收 `!consumed`。
  旧 `existing_keys` HashSet 实现已删（它从不回插新 key，重复 key 会误报）。
- **不变量**：id 沿用旧库（调课 override 挂 course_id，必须稳定）；Manual 永不
  参与 diff；退化匹配语义（class_id 缺失 → None）保留在五元组内。
- **回归测试**：`diff_pairs_same_class_multi_section_one_to_one`（3 条同 jxb
  多时段一对一、零变化、id 稳定）、`diff_duplicate_local_keys_only_one_consumed`
  （重复本地 key 只消费一条，多余停开）。
- **数据修复**：受污染的用户 `timetable.json` 已按教务真实数据重排（5 条坏课
  时段/周次逐一修正，id 不变），下次同步应零 diff。

### 20.2 公告解析：全校日期置换识别（修「解析错位」）

- **取证**（复用应用会话链路 example，已删）：用户点「关于9月20日课程补课安排
  的提醒通知」（jwc.cwxu.edu.cn/info/1100/5957.htm）——应用**确实抓到了正文**，
  正文第二行为「根据学校《关于2026年中秋、国庆放假安排的通知》要求，9月20日
  （星期日）补9月28日（星期一）课程」。旧解析器把书名号《…放假安排的通知》
  误提为课程名、摘录锚到首行「全体师生：」——不是抓错页面，是解析格式不匹配。
- **根因**：该通知是**全校日期置换**型（不含课程名/节次，课表层置换），旧
  `parse_notice_text` 只支持「某课程 调/停/补课」型。
- **修复**（`campus-schedule/src/notice.rs`）：新增
  `parse_notice_with_semester(text, courses, current_week, semester_start)`——
  先识别「M月D日（星期X）补N月N日（星期Y）课程」置换格式（相邻日期对 + 连接词
  补/上/按/换，括号星期提示优先、缺失时由学期锚点推算），对本地「被补日星期」
  每门未停开课产出一条 `Extra` 候选（周次=上课日所在教学周、星期=上课日当天、
  节次沿用原课）；未命中回落原 `parse_notice_text`（签名不变，测试不动）。
  缺学期锚点 → Low（reason 写明）；被补日无课 → 说明性候选（course_id 空）
  防前端静默空态。tauri 层 `parse_notice` / `parse_notice_from_url` 两处调用
  点改传 `tt.config.semester_start_date`。
- **边界**：置换解析需要 semester_start_date（融合门户同步已自动写入，
  §17.2）；采纳仍走候选确认流逐条确认，不自动 apply（§18.3 红线不变）。
