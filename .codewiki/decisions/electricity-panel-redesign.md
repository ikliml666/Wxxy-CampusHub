# 电费页重设计（M4 批 3，2026-09-19 用户裁决）

用户原话：「选择楼以及宿舍房间号需要使用前端技能重新设计，我觉得操作不够便捷」「整个页面卡片布局需要重新设计，两边有很多空白位置，卡片需要合理的设计，需要协调」。

## 五条决策

1. **容器 `max-w-3xl` 居中单列 → `max-w-5xl` 双列**（`lg:grid-cols-[minmax(0,1fr)_340px] lg:gap-4 lg:items-start`，窄屏自动塌成单列）。左列=操作主线（片区 / 查询房间余额，卡内含结果与常用房间区段 / 充值），右列=数据侧栏（电费变化 / 缴费记录）。栅格轨道必须 `minmax(0,1fr)` 且卡片内 `min-w-0`，否则长房间名会撑破布局。**这是「两侧大片空白」的根因修复**——原先所有面板都是 `max-w-3xl` 居中。（后续按用户要求把「常用房间」由右列独立卡并入查询卡内区段：它本质是查询入口，见 [[modules/electricity-panel|电费页]]。）
2. **校区唯一则自动选定**：判据**只有**「该层返回选项数 == 1」，绝不写死层名（将来学校加校区要能正确退回手动选）。三道防死循环闸：① 自动选定的 path 严格增长一级；② path 末段已等于该唯一选项时不再自动选（防服务端同层重发）；③ `MAX_CASCADE_STEPS = 10` 兜底。自动层在面包屑渲染为**非交互弱文本**「校区 · 无锡国际校区（自动）」，不占交互位。
3. **楼栋改卡片网格**（单击即进，不再用原生 `select`），房间号用**自动聚焦输入框 + 回车提交 + 「最近查过」chips**。**刻意不做屏幕数字小键盘**：桌面端物理键盘输入快于鼠标点数字，Tauri 桌面端没有虚拟键盘场景（若将来有触屏需求再加）。
4. **图表零依赖自绘**：项目没有图表库，趋势折线用内联 `<svg viewBox="0 0 100 40" preserveAspectRatio="none">` + 每段连续有效点一条 `<polyline vectorEffect="non-scaling-stroke">`，月度柱用 CSS 块。**`balance === null`（当天没采到）的点只占 x 位、断开线段**——不插值、不连过缺口、不画 0（把「没采」画成「余额 0」是错报）；有效点 < 2 个时给空态文案，**不画假线**。
5. **卡片高度协调**：识别「行数多但信息熵低」的块先砍——月度缴费原 12 行竖排（11 行是 0.00）占约 340px，改为「全年合计 + 只有缴费的月份 + 『其余 N 个月无缴费（0 元）』+ 展开全年」后约 150px；空态卡（未选片区 / 未绑定 / 有效点不足）一律用矮提示条，同一卡的多个空态**同构**（高度接近，绑定前后不跳变）。零值语义要在文案上写明，避免被误读成「取数失败」。

## 为什么这样取舍

- 用户要的是「更便捷」与「更协调」，而不是更多装饰：所以**不加动效、不引入依赖、不换配色**，只重排结构指纹（保留 `index.css` 全套域色/字号/圆角 token 与 `Surface` 域色角块语言）。
- 结果卡主数字读的是后端 `ElectricityView.balanceYuan`（结构化提取，见 [[decisions/electricity-daily-snapshot-and-merge|电费日快照与合并]]），**前端绝不解析 `fields` 自由文本**——实测原文 `当前余额837.47元,当前剩余电量1550.87度` 里同时有金额与 kWh，两处各写一份解析逻辑必然漂移。

## 已知边界

- 趋势折线的多日形态在交付时只有 1 个真实数据点（按设计走空态），多日渲染用临时注入的历史验证过（两段线在缺口日正确断开），真实形态待数据积累。
- 单价未在界面展示：`price` 未暴露到命令层，且实测 448 片区的 `price` 字段为 0，不可靠。
