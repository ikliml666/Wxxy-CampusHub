# 算术验证码识别：从 2.9% 到 100% 的五个根因

学校 CAS 的算术验证码（两一位数 + 运算符，PNG 100×25）最后用**零外部依赖的模板匹配**做到模板集/留出集各 100% 正确、0 自信错误。中途正确率一度只有 1.4%~2.9%，排查出**五个独立根因**，每一个都单独足以让识别失效——这是本文的价值所在。

## 根因一：彩色字符在灰度通道丢失形状

该校 Kaptcha **每个字符随机独立着色**（100 张样本出现 275 种主色），原来是按 `to_luma8()` 灰度 + Otsu 二值化。亮度与颜色无关：浅彩（淡黄/淡青/粉）字符灰度值接近白背景，被整片判为背景。

**修**：改用「到白色的距离」通道 `dist = 765 - Σrgb`（`captcha.rs:186` 一带）。该量与字符颜色成线性比例，再除以本图峰值即与颜色无关。固定阈值也会丢淡彩字符，故在距离图上做 Otsu 自适应（`captcha.rs:151`）。

## 根因二：片序理解错误（最隐蔽）

题面渲染顺序是 **「左操作数 运算符 右操作数 =」**，实现却按「数字、数字、运算符」取前 3 片——片 2（运算符）被当数字匹配、片 3（数字）被当运算符。模板库同时被按错误对应关系污染（`build_templates` 用同一错序）。

**症状特征**：每片最佳类得分 1.000（模板与样本同源）却仍失败——因为匹配的是错误位置。**修**：片序统一为 `[d1, op, d2]`，模板构建与识别共用（`captcha.rs:98`、`tests/captcha_solve.rs` 的 `chars = [d1, op, d2]`）。

## 根因三：细笔画块平均后变空网格

把 24×24 二值网格换成强度画布时，逐格取「源块前景占比 ≥0.5」判定。细笔画字符（`1`/`*`）的源块前景占比常态 0.2~0.6，**0.5 阈值下整片输出全 0**——所有空网格互相零距，表现为「不同字符零距对」168 个。

**诊断法**：打印零距对的前景格数（`fg=0` 即空网格），一眼定位。**修**：阈值降 0.2（`captcha.rs` patch_at 注释保留原因）。

## 根因四：平局判定用「模板间」差异，误杀全部

多模板策略下同类模板有 10 张：待识别片与自己的模板 NCC=1.000、与同类其他模板 0.95——差距 0.05 被 8% 平局阈值判为「区分不可靠」→ **100% 拒绝**。

**修**：先按字符类聚合取最大分，再跨类比较平局（`captcha.rs:105` 一带 `class_scores`）。语义上平局判定的对象是「不同的字符类」，不是「同一类的不同模板」。

## 根因五：求值 match 漏掉乘法分支

```rust
let val = match op {
    '+' => d1 + d2,
    '-' => d1 - d2,
    _ => return None,   // ← '*' 落到这里，乘法题（约占一半样本）全被拒
};
```
`_ => return None` 把漏写的分支伪装成「防御性兜底」，编译器不会报错。**教训**：对枚举/字符做穷举求值时，`_` 兜底前必须确认所有合法值都已显式列出；宁可用 `unreachable!()` 暴露遗漏。

## 阈值必须标定，不能猜

用「同类对 vs 异类对汉明/NCC 分布直方图」定阈值：24×24 二值网格下同类 min 0.931 / 跨类 max 0.839 有清晰分离带，阈值 0.88 一刀切。此前靠猜的 90/0.5/0.08 全是错的。

## 安全设计：宁拒不错

识别不出（返回 `None`）时**不提交登录**，只刷新验证码重试（≤3 张）——刷新不消耗 CAS 连续错误计数；而提交错误答案会计入计数，可能触发锁号。故评测指标分三类统计：正确 / 自信错误（红线，必须为 0）/ 拒绝（无害），见 `tests/captcha_solve.rs::captcha_solve_eval`。
